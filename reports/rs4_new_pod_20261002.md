## 6. Comprobar el run sin entrenar

El siguiente bloque sólo lee. Verifica archivos de ambas ramas, hashes congelados, contador del programa seleccionado y rutas BC. El mínimo 2.100M impide continuar inadvertidamente con la copia local antigua.

```bash
cd /workspace/HaxballRL
.venv/bin/python - <<'PY'
import json
from pathlib import Path
import torch
from tools.prepare_rs4 import file_hash
from train.runtime import load_config
from train.rs4_program import ProgramState

root = Path.cwd()
run = root / 'runs/rs4_v3_public'
required = ['specialization.json', 'ledger.json', 'parent.pt',
            'control/config.yaml', 'control/latest.pt',
            'memory/config.yaml', 'memory/latest.pt']
missing = [name for name in required if not (run / name).is_file()]
assert not missing, f'Run incompleto: {missing}'
manifest = json.loads((run / 'specialization.json').read_text())
ledger = json.loads((run / 'ledger.json').read_text())
assert manifest['kind'] == 'rs4_v3_program' and manifest['version'] == 3
checks = [('parent.pt', manifest['source_sha256'])]
if manifest.get('bc_teacher'):
    item = manifest['bc_teacher']
    checks.append((item['path'], item['sha256']))
checks += [(item['path'], item['sha256']) for item in manifest.get('historical_opponents', [])]
if ledger.get('champion', {}).get('sha256'):
    checks.append(('champion.pt', ledger['champion']['sha256']))
for name, expected in checks:
    assert (run / name).is_file(), f'Falta {name}'
    assert file_hash(run / name) == expected, f'Hash distinto: {name}'
branch = ledger.get('selected')
assert branch in ('control', 'memory'), f'No hay rama seleccionada: {branch}'
for candidate in ('control', 'memory'):
    cfg = load_config(run / candidate / 'config.yaml')
    ck = torch.load(run / candidate / 'latest.pt', map_location='cpu', weights_only=False)
    state = ProgramState.from_config(cfg, ck['rs4_program_state'])
    assert ck['steps'] == cfg['rs4_program']['start_steps'] + state.relative_steps
    teacher = cfg.get('bc_reference')
    if teacher:
        path = Path(str(teacher))
        path = path if path.is_absolute() else root / path
        assert path.is_file(), f'Falta BC: {path}'
        if manifest.get('bc_teacher'):
            assert file_hash(path) == manifest['bc_teacher']['sha256'], f'BC distinto: {path}'
    print(candidate, '| útiles:', state.relative_steps, '| fase:', state.phase['id'],
          '| deudas:', state.skill_debts, '| device:', cfg['ppo'].get('device'),
          '| Torch/física:', cfg['ppo'].get('torch_threads'), cfg['ppo'].get('numba_threads'))
    if candidate == branch:
        assert state.relative_steps >= 2_100_000_000, 'Checkpoint anterior al observado de 2.100M'
        assert not ledger.get('complete'), 'El programa ya figura completo; revisar antes de reanudar'
print('Run completo y referencias verificadas; rama seleccionada:', branch)
PY
```

Si la rama seleccionada muestra `device: cpu` y el nuevo Pod es GPU, cambiar únicamente el dispositivo en las configs, conservando copias originales:

## 7. Ejecutar con nohup y guardar logs

Preferencias del usuario: no usar tmux y ver primero logs de entrenamiento para conocer la velocidad. La primera medición se hace con el benchmark existente sobre una copia temporal del checkpoint seleccionado; realiza PPO, imprime cada iteración y descarta sus actualizaciones. No espera a la suite deportiva ni modifica los pesos, Adam, fase o contador del checkpoint de producción. Es una prueba de hardware independiente: su coste queda en `diagnostic_ppo_samples` del JSON, no se incorpora automáticamente al ledger cerrado del piloto de arquitectura. Conservar esa evidencia y no mezclarlo con progreso útil retenido del programa.

Después de instalar, verificar CUDA y recuperar el run completo, y sin otro entrenamiento/evaluación concurrente:

```bash
cd /workspace/HaxballRL
mkdir -p pod_logs runs/rs4_v3_public/hardware_checks
set -o pipefail
.venv/bin/python -u -m tools.benchmark_multitask --config runs/rs4_v3_public/control/config.yaml --checkpoint runs/rs4_v3_public/control/latest.pt --device cuda --torch-threads 2 --numba-threads 4 --warmup 3 --iters 10 --json-output runs/rs4_v3_public/hardware_checks/rtx3090_speed.json 2>&1 | tee pod_logs/rs4_speed.log
```

Usar `memory` en ambas rutas sólo si `ledger.json` indica esa rama seleccionada. La salida va a la consola y al archivo. Esperar a completar las tres iteraciones de calentamiento; Numba/CUDA pueden tardar en inicializar. Medir con la línea final `pasos/s reales`, cuyo denominador incluye el overhead medido, no sólo con `/s` de una iteración. Se conservan PPO, modelo, batch y mezcla guardados. Si la reconciliación posterior modifica la mezcla de compañeros y ejercicios, la velocidad real del programa puede cambiar; esta primera medición no certifica el throughput del nuevo perfil ni calidad deportiva.

El benchmark no tiene protección frente a cerrar la consola. Si se prefiere verlo y mantenerlo activo al desconectarse, usar nohup en lugar del pipeline anterior:

```bash
nohup .venv/bin/python -u -m tools.benchmark_multitask --config runs/rs4_v3_public/control/config.yaml --checkpoint runs/rs4_v3_public/control/latest.pt --device cuda --torch-threads 2 --numba-threads 4 --warmup 3 --iters 10 --json-output runs/rs4_v3_public/hardware_checks/rtx3090_speed.json >> pod_logs/rs4_speed.log 2>&1 < /dev/null &
echo $! > pod_logs/rs4_speed.pid
tail -n 40 -f pod_logs/rs4_speed.log
```

Log comunicado después: primera iteración 11.844 útiles/s por calentamiento; siguientes 102.591–115.190 útiles/s. La prueba se interrumpió con Ctrl+C en la iteración 6 de 13, por lo que no se produjo el resumen final de throughput inclusivo y puede faltar el JSON. Es evidencia preliminar: unos 15–17 minutos de PPO para 100M, más evaluaciones y overhead. El log corresponde a una copia temporal, muestra 2.100M propios y fase D; no acredita un avance de la producción. Los 6.640M del contador principal incluyen el ancla heredada.
